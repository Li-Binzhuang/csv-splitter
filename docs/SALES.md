# csvx 销售 one-pager（内部草案）

> 不是公开承诺；定价、SLA、合同需用户确认。当前代码无 License 强制、无遥测。

## 一句话
**把 100 GB CSV 变成可搜索、可编辑、可复现、可被 agent 调用的本地数据工作台。**

## 痛点
- 100 GB 导出文件：Excel 打不开，数据库导入慢、权限流程长；
- 对账/清洗靠脚本，改一次难复现、出错难回滚；
- LLM/Agent 只能看小样本，不能安全地在大文件上定位、编辑、导出。

## 三个可卖的能力（有实测证据）
1. **大文件交互**：104.5 GB/13 亿行 search 20.2 s、filter 25.8 s、全量导出 79.6 s，RSS <200 MB。
2. **可复现 Pipeline**：2.3 GB/9500 万行 filter→lookup→groupby 6.55 s；未变重跑 17 ms；失败不写坏输出。
3. **MCP 数据后端**：15 个只读/写工具 + 异步 job；schema→filter→view→edit→undo→convert 闭环，演示见 `docs/DEMO.md`。

## 客户样本报告

```bash
CSVX_PILOT_FILE=sample.csv CSVX_PILOT_WHERE=city=CDMX \
  python3 scripts/pilot_report.py
```

输出本地实测的扫描/导出/质量耗时与近似 RSS；见 `docs/PILOT.md`。这是试点交付物，
不是实验室 benchmark 的替代。

## 演示话术（5 分钟）
```bash
BIN=target/release/csvx bash scripts/demo_end_to_end.sh
```
- 先看 pipeline：两步 12/11 ms、重跑跳过；
- 再看 MCP：15 个工具、编辑/撤销、格式转换、后台 quality job；
- 最后打开 `docs/BENCHMARKS.md` 指 100 GB 数字。

## 常见异议
| 异议 | 回应 |
|---|---|
| “我们有数据库” | 不替代数据库；解决“导出文件到入库之间”的空档，且无需权限流程 |
| “Excel 就够了” | 10 GB+ 打不开、不能增量复现、不能给 agent 用 |
| “开源免费为什么付钱” | 免费核心保留；付费买自动化、支持、SLA、企业部署，不买“解锁已有功能” |
| “数据安全” | 纯本地、无遥测；可断网运行；不做多用户/云 |
| “没有 GUI” | CLI/MCP 是设计选择；演示与文档降低门槛，团队包提供培训 |
