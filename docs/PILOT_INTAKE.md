# 试点 intake（一页）

> 目标：用一份真实（可脱敏）数据，在 1 周内验证 csvx 是否能替代当前工具链。
> 不收集账号口令；不需要 PII/商业机密；样本用完即删。

## 客户需要提供

1. **一份样本文件**（任选）：
   - CSV / TSV / NDJSON / Parquet 之一；
   - 压缩可选 `.gz/.zst/.bz2`；
   - 建议 1–20 GB；若更大，先给 1 GB 切片。
2. **列说明**：每列含义、类型、是否允许空值。
3. **一个真实问题**：例如“按城市过滤后按客户分组求和”“找出重复订单”“MCP agent 要能分页查看”。
4. **验收口径**：当前工具耗时/RSS、期望结果、可接受的误差。

不需要提供：数据库密码、生产凭据、个人身份信息；如含敏感列请先脱敏或删列。

## 我们交付

- 用 `csvx pipeline` 复现问题，给出计划文件与运行结果；
- 用 `csvx mcp` 给出 agent 调用示例（schema/filter/search/view/job）；
- 一份 `docs/PILOT_SAMPLE.md` 风格的报告：墙钟、RSS、正确性对照、限制；
- 若结果不达标，明确说“不达标”，不包装成成功。

## 验收指标（建议）

| 维度 | 目标 |
|---|---|
| 结果正确性 | 与客户现有结果逐行/聚合对照一致 |
| 耗时 | 不超过当前工具的 80%，或单项 < 60 s |
| RSS | 单进程 < 200 MB（大文件扫描） |
| 集成 | MCP 客户端能完成一次完整查询 |
| 可复现 | 一条命令/一个 plan 文件重跑 |

## 排期（1 周）

1. 第 1 天：收样本与问题，确认脱敏与删除策略；
2. 第 2–3 天：跑 baseline 与 csvx，记录时间/RSS；
3. 第 4 天：修正口径/补功能，重跑；
4. 第 5 天：交付报告与是否进入付费试用的结论。

## 联系与边界

- 本仓库不提供 SaaS、GUI、多用户鉴权；试点是本地单用户。
- xlsx 暂不支持；Parquet 可用。
- 价格、SLA、合同需双方确认，本文档不是报价。
