# csvx 商业化假设（草案，2026-11-23）

> 这是产品方向的验证文档，不是定价承诺。任何收费、License 强制或遥测都需要用户确认；当前代码不包含这些。

## 1. 定位

**本地、单机、无服务依赖的 CSV 数据工作台。**
目标不是替代 Excel 或数据库，而是承接“10–100 GB 的 CSV 导出/日志/对账文件”：
- 打开就能分页、搜索、过滤，不用先导入；
- 可编辑且不改原文件（journal + undo）；
- 可声明式 pipeline 复现、增量刷新；
- 可被 agent/IDE 通过 MCP 直接调用。

## 2. 目标客户

| 客户 | 痛点 | 为什么愿意付费 |
|---|---|---|
| 数据工程/分析团队 | 100 GB 级 CSV 导入数据库慢、权限申请慢 | 本地 30 s 内搜索/过滤；pipeline 可复现 |
| 财务/运营对账 | 大表人工核对、Excel 打不开 | 编辑+撤销+质量报告；不破坏原始文件 |
| 隐私敏感行业 | 数据不能上云 | 纯本地、无遥测、无多用户服务 |
| Agent/IDE 用户 | LLM 只能看到小样本 | MCP 结构化工具 + 分页，给 agent 可控数据访问 |

## 3. 免费 / 付费边界（候选，未实施）

**保持免费且不回收**：
- 现有 CLI 核心：preview/view/filter/search/edit/journal/undo/analyze/convert/split/verify；
- 单机 MCP 只读工具；
- 文档与 benchmark。

**付费候选**（需要用户确认后才做代码门控）：
1. **Pipeline 自动化包**：调度、增量刷新告警、失败重试、运行历史保留；
2. **MCP 团队集成包**：连接器/客户端配置、审计日志、支持 SLA；
3. **企业部署包**：离线安装、版本锁定、安全评审材料、发票/合同；
4. **咨询/培训**：大文件工作流、数据对账、迁移。

不做：多用户鉴权、托管 SaaS、GUI。

## 4. 定价假设（待验证）

- 个人 Pro：一次性或年费，低于“一小时工程时间”的心理门槛；
- 团队包：按 3–10 人小团队年费，含 Pipeline/MCP 支持；
- 企业：按部署/支持合同报价。
具体数字不写死；先做 5 个设计伙伴，验证付费意愿与续费理由。

## 5. 验证实验（90 天）

| 实验 | 成功标准 |
|---|---|
| 20 次用户访谈 | 至少 8 人每月遇到 10 GB+ CSV |
| 5 个设计伙伴 | 3 个愿意把现有脚本迁到 pipeline |
| 2 个付费试点 | 至少 1 个签付费意向/合同 |
| MCP 集成 | 2 个 agent 客户端能完成“搜索→定位→编辑→导出”闭环 |
| benchmark | 100 GB 搜索/过滤数字可复现，成为对外材料 |

## 6. 风险

- CSV 是 commodity：护城河必须在**大文件体验 + 工作流 + agent 集成**，不是格式转换。
- DuckDB 依赖：构建体积/平台兼容性；需提供无 sql feature 的降级构建（已有）。
- 无 GUI：靠 CLI/MCP 获客，销售成本更高；需要极强文档与 demo。
- 性能承诺：只写实测数字，不写“理论峰值”。

## 7. 与当前路线图的关系

A（Pipeline）是付费自动化的基础；B（MCP）是 agent 集成的入口；C（100 GB）是对外性能证据。
每个里程碑至少产出一个可演示资产：benchmark、demo、集成截图/终端记录。
