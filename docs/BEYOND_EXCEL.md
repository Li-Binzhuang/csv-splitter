# 超越 Excel：路线与边界 / Beyond Excel

这份文件回答一个问题：**凭什么说这个后端可以比 Excel 更能处理数据。**
它只记录已经用测试或测量证明的事，以及还没做到、需要明确取舍的事。

## 已经超过 Excel 的地方（有数字）

| 维度 | Excel | 本项目 | 证据 |
|---|---|---|---|
| 行数上限 | 1 048 576 行 / 表 | 只受磁盘限制；2.5 GB / 684 917 行 × 782 列已实测可翻页 | `docs/CAPABILITIES.md` 实测表 |
| 打开成本 | 全量载入内存，大文件卡死 | 首屏 66 ms（含建索引），之后 6–7 ms | 同一实测表 |
| 并发 | 单用户，文件锁一写就冲突 | 8 个写者并发不丢编辑，锁冲突返回 409 | `concurrent_http_edits_all_land` |
| 自动化 | 宏 + COM，难在服务端跑 | HTTP API + `/capabilities` + `/spec` 机器可读契约 | `/spec` 与 18 路由字段守卫 |
| 编辑可审计 | 撤销栈随文件关闭即失 | journal sidecar，文件不动、操作可撤销可导出 | `/journal`、`edit export` |
| 公式列成本 | 写进单元格，复制整列 | **读时求值，不落盘**；加一列不复制数据 | `formula/mod.rs` 模块说明 |
| 大文件分析 | 透视表受内存限制 | DuckDB 引擎分流；原生与 SQL 双引擎等价有测试 | `engine.rs` 等价测试 |
| 分片与还原 | 手动另存 | `split` → `merge` 带片号/片数/行数清单三重校验 | merge 测试组 |

## 还没达到的部分（按优先级）

| # | 缺口 | 现在 | 下一步 | 验收 |
|---|---|---|---|---|
| 1 | **聚合公式**（SUM/AVERAGE/COUNTIF 对整列或区间） | 整列/条件聚合与 .agg 缓存（重复导出预扫约 30 ms）已实现；同一行的区间 `sum(B2:C2)` 也已支持；跨行区间未做 | 补跨行区间（需要随机访问或预扫）| 同一列 `sum()` 在 100 万行上单次 < 50 ms（重复导出预扫约 **30 ms**，达标；冷启动有 parquet 侧车约 **50 ms**、无侧车约 **80 ms**，仍略高于目标） |
| 2 | **跨表引用** | `lookup`/`ref()` 可跨文件取列，但公式里没有 `Sheet!A1` 语法 | 引入 `book` 内的表名引用，只读、带缓存 | 跨表公式与 `lookup` 结果一致 |
| 3 | **xlsx 读写** | 明确不做（当前硬约束）| 可选：仅导出（写好表头/类型），不引进 xlsx 解析器 | 需要用户解除约束 |
| 4 | **图形界面** | 无（HTTP API + 内置浏览页） | 可选：独立前端消费现有端点 | 需要用户确认 |
| 5 | **多操作事务块** | `set-many`（仅赋值）与 `POST /edit?action=transaction`（set/delete/insert）都先校验、再一次 journal 写入：一批失败**一条都不写**；`.journal.blocks` 记下批次边界，`edit undo`/`action=undo` **一次撤销整批** | — | 一批失败全部不生效；CLI 与 HTTP 均有整批撤销测试 |
| 6 | **公式重算性能** | 读时求值，每次读重算 | 可选：按 journal 版本缓存计算结果 | 重复读同一屏 < 2 ms |

## 明确的非目标

- 不做多用户鉴权（服务只绑回环地址，靠部署侧隔离）。
- 不做 xlsx 解析（除非用户解除约束）。
- 不做宏/VBA。

## 判断标准

任何一项「超越」都必须同时满足：

1. **可测量**：给出数字，不是形容词；
2. **有测试**：行为被测试钉住，而不是一次演示；
3. **不撒谎**：做不到的部分写进上表，而不是藏在文档角落。
